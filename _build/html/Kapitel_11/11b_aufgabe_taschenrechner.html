Aufgabe: Taschenrechner

Development Expert Python / PCAP  |  Kapitel 11: GUI  |  Aufgabe 11b

Aufgabe

Baue einen einfachen Taschenrechner als tkinter-Anwendung. Die Anwendung nimmt zwei Zahlen entgegen, der Nutzer wählt eine Operation und bekommt das Ergebnis angezeigt.

Die Aufgabe ist in vier Schritte aufgeteilt. Jeder Schritt baut auf dem vorherigen auf. Lies den gesamten Schritt durch bevor du anfängst zu coden.

Einschränkung: Nur die Konzepte aus 11a und 11b -- Entry, Label, Button, Frame, grid, pack, Callbacks, try/except. Kein eval(), keine neuen Widgets.

Kursinhalt Das Ziel

Am Ende dieser Aufgabe soll eine Anwendung laufen die so aussieht und sich so verhält:

┌─────────────────────────────────┐
│  Zahl 1:  [ 12          ]       │
│  Zahl 2:  [ 4           ]       │
│                                 │
│  [ +  ]  [ -  ]  [ *  ]  [ /  ]│
│                                 │
│  Ergebnis:  12 / 4 = 3.0        │
└─────────────────────────────────┘

  • Zwei Eingabefelder für die Zahlen

  • Vier Buttons für die vier Grundrechenarten

  • Ein Ergebnisbereich der die vollständige Rechnung anzeigt: 12 / 4 = 3.0

  • Fehlerbehandlung: Division durch null und ungültige Eingaben werden abgefangen und als lesbare Meldung angezeigt – kein Programmabsturz

Schritt 1 Das Fenster und die Eingabefelder

Erstelle eine neue Datei taschenrechner.py und baue das Grundgerüst.

Was in diesem Schritt entsteht: Ein Fenster mit zwei beschrifteten Eingabefeldern und dem Grundgerüst für die nächsten Schritte. Noch keine Buttons, noch keine Logik.

Aufgaben:

  1. Importiere tkinter.

  2. Erstelle ein Hauptfenster mit einem passenden Titel und einer festen Startgröße. Die Größe soll vom Nutzer nicht verändert werden können.

  3. Erstelle zwei beschriftete Eingabefelder – eines für “Zahl 1” und eines für “Zahl 2”. Platziere Label und Entry nebeneinander mit grid().

  4. Starte die Ereignisschleife.

Hilfestellungen:

Aus 11a: root.resizable(False, False) verhindert dass das Fenster vergrößert werden kann.

Aus 11a: grid(row=, column=, sticky=, padx=, pady=) platziert Widgets in einem Raster. sticky='w' richtet ein Widget linksbündig in seiner Zelle aus.

Aus 11a: columnconfigure(n, weight=1) erlaubt einer Spalte beim Vergrößern zu wachsen – hier noch nicht nötig, aber gut zu wissen.

Speichere die beiden Entry-Widgets in Variablen – du wirst sie in Schritt 3 brauchen um mit .get() die Eingaben auszulesen.

import tkinter as tk

from Kapitel_11.tkinter_test import button_frame, ergebnis_label

root = tk.Tk()
root.title('Calculator')
root.geometry('320x200')
root.resizable(False, False)

eingabe_frame = tk.Frame(root)
eingabe_frame.pack(padx=20, pady=(18,8), fill='x')

tk.Label(eingabe_frame, text='Zahl 1:').grid(row=0, column=0,pady=4)
eingabe1 = tk.Entry(eingabe_frame, width=18)
eingabe1.grid(row=0, column=1, sticky='ew', padx=(10,0),pady=4)

tk.Label(eingabe_frame, text='Zahl 2:').grid(row=1, column=0,pady=4)
eingabe2 = tk.Entry(eingabe_frame, width=18)
eingabe2.grid(row=1, column=1, sticky='ew', padx=(10,0),pady=4)

root.mainloop()

  • Kann man in beide Felder tippen?

  • Lässt sich die Fenstergröße nicht verändern?

Wenn ja: weiter mit Schritt 2.

Schritt 2 Die Operatoren-Buttons

Füge vier Buttons für +, -, * und / hinzu. Die Buttons sollen nebeneinander in einer Reihe liegen.

Was in diesem Schritt entsteht: Die vier Operator-Buttons sind sichtbar und klickbar – sie tun beim Klicken aber noch nichts, weil die Berechnungsfunktionen erst in Schritt 3 kommen.

Aufgaben:

  1. Erstelle einen Frame für die vier Buttons.

  2. Platziere den Frame unterhalb der Eingabefelder.

  3. Erstelle die vier Buttons im Frame und platziere sie nebeneinander.

  4. Gib jedem Button einen command=-Parameter – die Funktion die aufgerufen wird existiert noch nicht, aber du kannst schon mal einen Platzhalter angeben: command=lambda: None.

Hilfestellungen:

Aus 11a: Ein tk.Frame ist ein unsichtbarer Container. Innerhalb des Frames kannst du pack(side='left') benutzen um die Buttons nebeneinander zu platzieren – auch wenn du im restlichen Fenster grid() verwendest. Pack und grid dürfen nicht im selben Container gemischt werden, aber ein Frame im grid-Container der intern pack benutzt ist erlaubt.

Aus 11a: padx= bei .pack() fügt Außenabstand links und rechts eines Widgets hinzu.

Aus 11b: command=lambda: None ist ein gültiger Platzhalter. None bedeutet “tue nichts” – später ersetzt du None durch den echten Funktionsaufruf.

Tipp: Alle vier Buttons rufen dieselbe Berechnungsfunktion auf – aber mit verschiedenem Argument ('+', '-', '*', '/'). Denke schon mal daran wie du das mit lambda lösen wirst.

#--- Buttons ----

button_frame = tk.Frame(root)
button_frame.pack(pady=8)

for op in (' + ',' - ',' * ',' / '):
    tk.Button(
        button_frame,
        text= op,
        command=lambda: None
    ).pack(side='left', padx=6)
Selbsttest nach Schritt 2

  • Sind alle vier Buttons sichtbar und in einer Reihe?

  • Reagieren die Buttons auf Klicks – ohne dass das Programm abstürzt?

  • Passiert beim Klicken (noch) nichts, weil der Platzhalter lambda: None verwendet wird?

Wenn ja: weiter mit Schritt 3.

Schritt 3 Die Berechnungslogik

Jetzt kommt die eigentliche Logik. Schreibe eine Funktion berechne(operator) die aufgerufen wird wenn der Nutzer einen Operator-Button klickt.

Was in diesem Schritt entsteht: Der Taschenrechner rechnet. Klickt man auf +, werden die zwei Zahlen addiert und das Ergebnis erscheint im Fenster.

Aufgaben:

  1. Erstelle ein Label das das Ergebnis anzeigt. Platziere es unterhalb der Buttons. Am Anfang ist es leer.

  2. Schreibe die Funktion berechne(operator). Sie soll:

    • Die Werte aus beiden Entry-Feldern mit .get() auslesen

    • Die Werte von String in Zahl umwandeln

    • Je nach operator die passende Rechenoperation ausführen

    • Das Ergebnis als vollständige Rechnung im Label anzeigen: 12 + 4 = 16

  3. Verbinde die Buttons mit der Funktion: Ersetze lambda: None durch den richtigen lambda-Aufruf.

Hilfestellungen:

Aus 11b: entry.get() gibt immer einen String zurück. float('12') wandelt ihn in eine Zahl um. Warum float statt int? Weil der Nutzer auch Dezimalzahlen eingeben können soll.

Aus 11b: label.config(text='...') aktualisiert den angezeigten Text eines Labels.

Aus 11b: command=lambda: berechne('+') – so übergibt man den Operator als Argument. Der lambda f=farbe-Trick aus dem Schleifenbeispiel ist hier nicht nötig, weil die Werte nicht aus einer Schleife kommen.

Für die vier Operationen brauchst du keine externe Bibliothek. a + b, a - b, a * b, a / b reichen vollständig.

Tipp für die Anzeige: f-Strings machen das einfach. f'{a} {operator} {b} = {ergebnis}' ergibt zum Beispiel '12.0 + 4.0 = 16.0'.

def berechne(operator):
    try:
        a = float(eingabe1.get())
        b = float(eingabe2.get())
    except ValueError:
        ergebnis_label.config(
            text='Fehler bitte zwei gültige Zahlen eingeben',
            fg='red'
        )
        return

    if operator == ' / '  and b == 0:
        ergebnis_label.config(
            text='Fehler: Division durch null',
            fg='red'
        )
        return

    if operator == ' + ':
        ergebnis = a + b
    if operator == ' - ':
        ergebnis = a - b
    if operator == ' * ':
        ergebnis = a * b
    if operator == ' / ':
        ergebnis = a / b

    def fint(n):
        return int(n) if n == int(n) else n

    ergebnis_label.config(
        text=f'{fint(a)} {operator} {fint(b)} = {fint(ergebnis)}',
        fg='black'

    )

#---Ergebnis---

ergebnis_label = tk.Label(root, text ='',font=('Arial', 11))
ergebnis_label.pack(pady=6)

Schritt 4 Fehlerbehandlung

Ein robuster Taschenrechner darf nicht abstürzen – egal was der Nutzer eingibt. Es gibt zwei Fehlerfälle die abgefangen werden müssen.

Was in diesem Schritt entsteht: Der Taschenrechner zeigt bei ungültigen Eingaben eine lesbare Fehlermeldung im Ergebnis-Label an, statt abzustürzen oder einen Python-Traceback anzuzeigen.

Aufgaben:

Erweitere die berechne()-Funktion so dass sie zwei Fehlerfälle abfängt:

  1. Ungültige Eingabe: Der Nutzer hat kein Feld ausgefüllt oder Text statt einer Zahl eingegeben. Zeige dann im Ergebnis-Label die Meldung: 'Fehler: Bitte zwei gültige Zahlen eingeben.'

  2. Division durch null: Der Nutzer hat 0 als zweite Zahl eingegeben und / geklickt. Zeige dann: 'Fehler: Division durch null.'

Hilfestellungen:

Aus 11b: try/except in Callbacks ist Pflicht. Welcher Fehler wird geworfen wenn man float('') aufruft? Welcher wenn man durch null teilt?

Tipp: Python wirft bei Division durch null einen ZeroDivisionError. Du kannst ihn mit except ZeroDivisionError separat abfangen – oder du prüfst vorher mit if b == 0 ob der Nenner null ist.

Tipp: Es gibt zwei Strategien um mehrere Fehlerfälle abzufangen. Entweder mehrere except-Blöcke hintereinander – oder ineinander verschachtelte try/except. Welche Variante macht hier mehr Sinn?

Aus 11b: label.config(fg='red') färbt den Text rot. label.config(fg='black') setzt ihn zurück. Nutze das um Fehlermeldungen von normalen Ergebnissen zu unterscheiden.

Kursinhalt Optionale Erweiterungen

Der Taschenrechner funktioniert. Wer noch weitermachen will, kann die folgenden Erweiterungen einbauen – alle sind mit den Mitteln aus 11a und 11b umsetzbar.

Enter-Taste: Aus 11b: entry.bind('<Return>', ...). Welchen Operator soll Enter auslösen? Überlege wie du den zuletzt geklickten Operator speicherst – zum Beispiel in einer Variable die beim Klick auf einen Operator-Button aktualisiert wird.

Leeren-Button: Ein Button der beide Entry-Felder leert und das Ergebnis-Label zurücksetzt. Welche Methode aus 11b löscht den Inhalt eines Entry-Felds?

Ergebnis in Zahl 1 übernehmen: Ein Button “Ergebnis übernehmen” der das berechnete Ergebnis in das erste Eingabefeld schreibt – für Kettenrechnungen. Denk daran dass du das Ergebnis irgendwo gespeichert haben musst um es später abrufen zu können.

Ganzzahlen sauber anzeigen: Gerade wird 10.0 + 5.0 = 15.0 angezeigt – auch wenn das Ergebnis ganzzahlig ist. Wie kannst du prüfen ob ein Ergebnis ganzzahlig ist und es dann ohne Dezimalstelle anzeigen? Stichwort: ergebnis == int(ergebnis).
